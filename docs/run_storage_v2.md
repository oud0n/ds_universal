# 走行の記録の形の見直し（runs.json の 2 版。案）

2026-10-24。PLAN-29 の残り（走行を表す名前・相手の動画の同期の保存・ログの ID に頼る同期）と、PLAN-32（走行の名前）・PLAN-33（走行のメモ）の置き場を、使う人が増える前に決める。docs/session_storage_design.md の続き。

## 今の形の問題

1. **古い版が新しい項目を消す**。1.0.2 は runs.json を書き直すとき、知っている項目（`updatedAt`・`videos`・`sync`）だけを残して、全部の走行の行を作り直す。1.0.3 で項目を足しても、1.0.2 の PC 版が同じフォルダに書くと消える。laptimes.json も同じ。
2. **同じ走行が 2 行になる**。行の名前がファイル名（`20260918/20260918092608.nmea` と `.bon4`）なので、同じ走行に 2 つの行ができ、どちらを使うかを名前の比べ方で探している。
3. **同期がログの ID に頼っている**。`sync` は同期プロジェクトの形のままで、`matchedSessionId`・`clock.logId`・`sessions[].id` は開くたびに変わる ID（`sess_…`）。開くたびに、保存したときのログの一覧から今のログへ読み替えている。
4. **比べる相手（Car 2〜4）の動画の同期を直しても残らない**。runs.json に書くのは、Car 1 の走行の動画だけ。
5. **利用者が付けた情報が控えに入っている**。隠した周は laptimes.json（作り直せる控え）にある。同期ピンはサーキットごとに端末の中（localStorage）にあり、別の端末に引き継がれない。
6. 走行の名前（PLAN-32）・メモ（PLAN-33）の置き場がない。

## 案（レビューのあと。2026-10-24）

### 1. 知らない項目を残す

runs.json を読んで書き直すとき、知らない項目（上の段・走行の行の中・動画の中）をそのまま残す。これから先の版で項目を足しても、1.0.3 以降の版は消さない。laptimes.json は 1.0.2 が丸ごと作り直すので、新しい情報は入れない。

### 2. runs.json を 2 版にする

`"version": 2`。1.0.3 は 1 版も読み、**その走行の中身が変わったときだけ**、ファイル全体を 2 版にして書く。

```json
{
  "version": 2,
  "runs": {
    "20260918/20260918092608": {
      "id": "r_8f3k2m9q",
      "updatedAt": "2026-10-24T03:12:00Z",
      "name": "雨の 1 本目",
      "note": "気温 18℃、タイヤ 2.1",
      "parts": { "1": { "clockOffsetSec": 0 } },
      "videos": [
        {
          "name": "GX010017.MP4",
          "size": 3174382666,
          "durationSec": 1692.18,
          "recordedAt": "2026-09-18T00:27:35.000Z",
          "timezone": { "video": "JST", "gps": "JST" },
          "chosen": false,
          "clock": { "source": "manual", "logPart": 1, "offsetSec": 129.538, "utcMs": 1789691297388.3 },
          "pins": [{ "name": "1コーナー", "logPart": 1, "logTimeSec": 512.3, "videoTimeSec": 498.1, "utcMs": 1789691809688 }]
        }
      ]
    }
  }
}
```

- **行の名前は走行の名前**（`日付のフォルダ/拡張子なしの名前`。日付のフォルダの無い古い走行は名前だけ）。`.nmea` と `.bon4` は 1 つの行。
- **`id`**: 初めて書くときに付ける、変わらない印。解析用のセッション（PLAN-18）・参考ラップ（PLAN-31）は、この印で走行を指す（ファイルを日付のフォルダへ移しても切れない）。
- **ログの ID（`sess_…`）を書かない**。動画の時刻（`clock`）は 2 通り:
  - `logPart` が数: その走行のログ（分かれた走行は何番目か。分かれていなければ 1）の先頭からの `offsetSec` 秒で決めた時刻（手で合わせた、など）。
  - `logPart` が `null`: `utcMs`（世界の時刻）で決めた時刻（GPS・撮影日時から）。`offsetSec` は使わない。
  - どちらも `utcMs` を入れておく（ログを読まずに開いても位置が分かる）。
- **書くときは、その行の走行のログで表し直す**。比べる相手（Car 2〜4）の動画を手で合わせると、今は Car 1 のログで表した時刻になる。そのまま書くと、相手の走行の行で別のログからの秒と読まれてずれるので、相手の走行のログでの秒に直して書く（そのログに時刻が無いときは `utcMs` だけで書く）。
- **ログの時計の補正は、分かれた走行の何番目ごと**（`parts`）。
- **同期ピンは動画ごと**。時刻は、その行の走行のログで表し、`utcMs` も持つ。
- `chosen`: 動画を出すログを手で選んだか（今の `sessionChosenManually`）。
- `name`・`note` は PLAN-32・PLAN-33 の置き場（画面は後でよい）。参考ラップ（PLAN-31）の印（`kind: "reference"`・`driver`）は、そのときに足す（知らない項目は残るので、足しても古い 1.0.3 が消さない）。

### 3. 隠した周は laptimes.json のまま（今回は移さない）

レビューで、移すと 1.0.2 と 1.0.3 で 2 か所に分かれ、隠すのをやめても片方から戻る・ラップタイマーの「これまでのベスト」が片方しか見ない、と分かった。laptimes.json の隠した周は、作り直しても引き継がれ、どちらの版も読み書きするので、今は移さない。1.0.2 が使われなくなってから見直す。

### 4. 比べる相手の動画の同期も、その走行の行に書く

開いている動画ごとに、どの走行の動画か（保管場所の道）を持ち、同期が変わったら、その走行の行に書く（上の「表し直す」をして）。Car 1 か Car 2〜4 かは問わない。

### 5. 開いただけでは書かない

今は、開いて画面を触っただけ（カメラの枠を替えた、など）で runs.json を書いている。2 版にするのは中身が変わったときだけにしたいので、書く前に、開いたときの中身（2 版の形）と比べ、同じなら書かない。

### 6. 端末の間でぶつかったとき

- 今と同じ（書く直前に読み直し、変えた行だけ差し替える）。
- iCloud が作るぶつかったときの写し（`runs 2.json` など）も読み、行ごとに新しい `updatedAt` のほうを使う。次に書くときに、本体に入れる（写しを消すのは後で）。
- デスクトップ版で、iCloud にだけある（端末に落ちてきていない）runs.json を「無い」と読んで、新しく作ってしまわないようにする（`.runs.json.icloud` があれば読めないとみなす）。

### 7. 分かれた走行の数え方をそろえる

記録の空き（10 分）で走行を分けるとき、.bon4 の読み込み・.nmea の読み込み・周の控え（lapIndex）で、短い切れ端の捨て方が違う（.bon4 は 10 秒未満を捨てる、.nmea は捨てない）。同じ走行で何番目かがずれるので、1 つの決まり（2 点以上・10 秒以上）にそろえる。

## 移し替え

- 1 版のファイルは、読むときに 2 版の形に読み替える。書くのは中身が変わったときだけで、そのときファイル全体を 2 版にする。読み替えられない行は、そのまま残す（捨てない）。
- 同じ走行の 2 行（`.nmea` と `.bon4`）は、新しい `updatedAt` のほうを使う（動画を外した行と合わせると、外した動画が戻るため）。
- 1 版の `clock.logId` は、行の中の `sessions` の名前（`名前_2` なら 2 番目）で `logPart` に読み替える。見つからないときは `utcMs` で決めた時刻にする（動画を捨てない）。
- 端末の中の同期ピン（サーキットごと）は、その走行の動画に付いたものだけを写す。端末の中のピンは消さない（同じ端末の 1.0.2 が使うため）。同じ名前・同じ時刻のピンは重ねない。
- `.dssync.json`（同期の書き出し・読み込み）は今の形のまま（保管場所の外の動画とログ用）。

## 1.0.2 で 2 版のフォルダを開いたとき（確かめた）

- 2 版を読めないので、走行に付けた動画が無いとみなし、同じフォルダの近い時刻の動画を自動で付け直す（手で合わせた同期は使われない）。
- 書こうとしても、読めない形のファイルには書かない作りなので、2 版のファイルは消えない。ただし 1.0.2 で直した同期は残らない（知らせも出ない）。
- 1.0.3 に上げれば、2 版の同期がそのまま使われる。

## 見送るもの

- 隠した周を runs.json へ移す（上の 3）。
- iPhone のアプリの中（LapTimer/）と選んだフォルダの 2 つの置き場を 1 つにする（BUG-30 で、測り終えたらフォルダへ移す形になった）。
- 解析用のセッションのファイル（PLAN-18）: 走行は `id` と行の名前で指す（session_storage_design.md の例を直す）。

## 決めたこと（2026-10-24）

- runs.json を 2 版にする。1.0.2 で 2 版のフォルダを開くと、走行に付けた動画・同期が使われない（消えはしない）が、それでよい。
- 同期ピンは、端末の中（サーキットごと）から runs.json（動画ごと）へ移す。
- 作る前に Fable・agy でこの案をレビューする。
- レビュー（Fable・agy Argon Medium）を受けて: 隠した周は移さない、時刻は「ログの何番目から」と「世界の時刻」を分けて持つ、相手の動画の時刻はその走行のログで表し直す、走行に変わらない印（id）を付ける、開いただけでは書かない、ぶつかったときの写しを読む、分かれた走行の数え方をそろえる。
