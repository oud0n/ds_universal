# 走行の記録の形の見直し（runs.json の 2 版。案）

2026-10-24。PLAN-29 の残り（走行を表す名前・相手の動画の同期の保存・ログの ID に頼る同期）と、PLAN-32（走行の名前）・PLAN-33（走行のメモ）の置き場を、使う人が増える前に決める。docs/session_storage_design.md の続き。

## 今の形の問題

1. **古い版が新しい項目を消す**。1.0.2 は runs.json を書き直すとき、知っている項目（`updatedAt`・`videos`・`sync`）だけを残して、全部の走行の行を作り直す。1.0.3 で項目を足しても、1.0.2 の PC 版が同じフォルダに書くと消える。laptimes.json も同じ。
2. **同じ走行が 2 行になる**。行の名前がファイル名（`20260918/20260918092608.nmea` と `.bon4`）なので、同じ走行に 2 つの行ができ、どちらを使うかを名前の比べ方で探している。
3. **同期がログの ID に頼っている**。`sync` は同期プロジェクトの形のままで、`matchedSessionId`・`clock.logId`・`sessions[].id` は開くたびに変わる ID（`sess_…`）。開くたびに、保存したときのログの一覧から今のログへ読み替えている。
4. **比べる相手（Car 2〜4）の動画の同期を直しても残らない**。runs.json に書くのは、Car 1 の走行の動画だけ。
5. **利用者が付けた情報が控えに入っている**。隠した周は laptimes.json（作り直せる控え）にある。同期ピンはサーキットごとに端末の中（localStorage）にあり、別の端末に引き継がれない。
6. 走行の名前（PLAN-32）・メモ（PLAN-33）の置き場がない。

## 案

### 1. 知らない項目を残す（1.0.3 で必ず入れる）

runs.json・laptimes.json を読んで書き直すとき、知らない項目（上の段・走行の行の中）をそのまま残す。これから先の版で項目を足しても、1.0.3 以降の版は消さない。

### 2. runs.json を 2 版にする

`"version": 2`。1.0.2 は 2 版を読まず（走行に動画が付いていないように見える）、書きもしない（読めない形には書かない作りなので、消さない）。1.0.3 は 1 版も読み、初めて書くときに 2 版にする。

```json
{
  "version": 2,
  "runs": {
    "20260918/20260918092608": {
      "updatedAt": "2026-10-24T03:12:00Z",
      "name": "雨の 1 本目",
      "note": "気温 18℃、タイヤ 2.1",
      "hidden": [{ "n": 7, "startMs": 1789691400000 }],
      "clockOffsetSec": 0,
      "videos": [
        {
          "name": "GX010017.MP4",
          "size": 3174382666,
          "durationSec": 1692.18,
          "recordedAt": "2026-09-18T00:27:35.000Z",
          "clock": { "source": "gps", "offsetSec": 0, "utcMs": 1789691297388.3, "part": null },
          "timezone": { "video": "JST", "gps": "JST" },
          "pins": [{ "name": "1コーナー", "logTimeSec": 512.3, "videoTimeSec": 498.1 }]
        }
      ]
    }
  }
}
```

- **行の名前は走行の名前（日付のフォルダ/拡張子なし）**。`.nmea` と `.bon4` は 1 つの行。
- **ログの ID を書かない**。動画はその行の走行のもの。時刻の元のログは「この走行」（分かれた走行は `part`）。
- **隠した周（`hidden`）を runs.json に移す**。laptimes.json の `hidden` も読み、合わせて使う（古い版で隠した周も消えない）。
- **同期ピンは動画ごとに runs.json に持つ**（端末の中の、サーキットごとのピンからは、開いたときに一度だけ写す）。
- `name`・`note` は PLAN-32・PLAN-33 の置き場（画面は後でもよい。形だけ先に決める）。

### 3. 比べる相手の動画の同期も、その走行の行に書く

開いている動画ごとに「どの走行の動画か」（保管場所の道で分かる）を持ち、同期が変わったら、その動画の走行の行に書く。Car 1 か Car 2〜4 かは問わない。

### 4. 端末の間でぶつかったとき

今と同じ（書く直前に読み直し、変えた行だけ差し替える）。`hidden` は両方を合わせる。

## 移し替え

- 1 版の行は、読むときに 2 版の形に読み替える（同じ走行の 2 行は、新しい `updatedAt` のほうを使い、`hidden` は合わせる）。ログの ID は、行の中の `sessions` から「この走行」に読み替える。
- 書くのは、その走行を書き換えたとき（開いて同期を直した・周を隠した、など）。開いただけでは書かない。
- `.dssync.json`（同期の書き出し・読み込み）は今の形のまま残す（保管場所の外の動画とログ用）。

## 見送るもの

- iPhone のアプリの中（LapTimer/）と選んだフォルダの 2 つの置き場を 1 つにする: BUG-30 で、測り終えたらフォルダへ移す形になったので、今は直さない。
- 解析用のセッションのファイル（PLAN-18）: 形は session_storage_design.md のまま。2 版の行の名前（走行の名前）で走行を指す。

## 決めたこと（2026-10-24）

- runs.json を 2 版にする。1.0.2 で 2 版のフォルダを開くと、走行に動画が付いていないように見える（消えはしない）が、それでよい。
- 同期ピンは、端末の中（サーキットごと）から runs.json（動画ごと）へ移す。
- 作る前に Fable・agy でこの案をレビューする。
