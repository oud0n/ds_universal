# 実機での確認 (2026-10-25、feat/android)

1.1.0 の前に、実機でしか分からないものを確かめる。「自動」は Mac につないだ端末を Claude が CDP で動かして確かめるもの、「手で」は利用者が操作するもの。

## つなぐ前に

- iPhone: USB でつなぎ、画面のロックを外しておく (入れ直しと CDP に要る)。「このコンピュータを信頼」が出たら許可
- Android: エミュレーター (laploupe_test) は Claude が動かす。友人の端末は手で (APK を渡す)

書き込むもの (★) は、保管場所に試験用のフォルダ `e2e_test/` を作って試し、終わったら消す。★ は始める前に利用者に確かめる。

## 結果

### 2026-10-25 夜 (自動。iPhone 17 Pro Max・Android エミュレーター)

| # | 結果 |
|---|---|
| A1 | OK。最新のビルドを入れて起動 |
| A2 | OK。走行の画面・参考ラップの区切り (参考ラップが無いときの案内)・消す確かめの画面に崩れなし (縦だけ。横は端末を回せないので未) |
| A3 | OK。e2e_test/ の同じ日の 2 本のうち 1 本を消し、ログ・センサーの .csv・内蔵カメラの動画だけが消え、もう 1 本と付けていない動画は残った。runs.json も消した走行の行だけ消えた。iCloud のフォルダではゴミ箱へ移り、「すぐ消した」知らせは出なかった。ほかの走行の動画の理由が「付けていない動画」と出ていたので「ほかの走行のファイル」に直した |
| A4 | OK。9/18 L10 と 8/15 L1 を保存 → 8/30 を開く → 開き直すと同じ 2 台・同じ周に戻った。消すと一覧から消えた |
| A5 | 見つけて直した: iPhone では、印を打つ画面・比べるの動画が、止めたままだと黒いまま (一度再生するまでコマを描かない) で、今の位置の表示も 0:00 のまま。長さが分かった時点で音を消して一瞬再生して止める・位置は 0.1 秒ごとに読む形にして、コマが出て 1 コマ送り (+0.033 秒) も効くのを確かめた。比べるの再生は 2 つの動画が 0.1 秒以内でそろった |
| A6 | OK。過去のログの再生で、後ろ・前の 2 本の .mov ができた (12 秒で 11 MB・16 MB、どちらも縦向き)。再生には走行のファイルが無いので unsorted/ に入る (試験のあと消した) |
| A7 | 見つけて直した: Android の動画の読み出しで、WebView が Range の頭まで自分で読み飛ばすのに、こちらでも頭へ動かしていて 2 回飛ばしていた。ファイルの後ろ半分が読めず、前半も違う中身を返していた。後ろに目次 (moov) のある動画 (GoPro・iPhone・ffmpeg の既定) は再生できなかった (0.2.1 までの不具合)。頭から渡して end で止める形に直し、どの位置も中身がファイルと一致し、目次が後ろの動画が再生・移動できるのを確かめた。動画の URL の頭 (Android は https) を聞く前に動画を出していたのも直した。選んだフォルダでの走行を消す・動画だけの参考ラップの保存は OK |
