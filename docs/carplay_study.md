# CarPlay 対応の調査（2026-10-25）

結論: **実質不可として見送る。** 今のラップタイマーの横画面をそのまま CarPlay に出すことはできず、出せるもの（周ごとに変わる文字と、測定開始・終了のボタン）だけでは作る意味が薄いため。

## 1. やりたかったこと

ラップタイマーの横画面（今の周のタイマー・タイム差のバー・速度・前の周・ベスト・セクター）を、車の CarPlay の画面にそのまま出す。

## 2. CarPlay の決まり

- **アプリが描いた画面は出せない。** CarPlay のアプリは、Apple が用意した型（文字の情報・ボタンの並び・一覧など）を組み合わせて画面を作る。自分で描ける（地図の部分）のはナビのアプリだけで、その許可は道案内をするナビにしか出ない。
- **iPhone の画面を映す機能（ミラーリング）は無い。**
- **分類ごとの許可（entitlement）が要る。** ラップタイマーが入れそうなのは「運転の作業（Driving Task、iOS 16 から）」。Apple に申し込み、認められた場合だけ使える。
- 運転の作業の分類の決まり（WWDC22 と CarPlay Developer Guide 2026-10 版から）:
  - 対象は「運転そのものを助ける作業」（運転中にするだけの作業は対象外）。例は、車の付属品の操作・運転と道路の状態の情報・運転の始めと終わりの作業。
  - 画面は最小限で、数秒で済む作業だけ。設定・サインインなどは出さない。
  - 表示も操作も、用意された型を使う。型の数（画面の深さ）は 2 まで（フォーラムの書き込みより。古い可能性あり）。
  - **CarPlay の画面の値を、10 秒より短い間隔で定期的に書き換えてはいけない（例: 刻々と変わるエンジンの値は出せない）。** ガイドに明記されている。

## 3. ラップタイマーに当てはめると

| 出したいもの | 可否 | 理由 |
|---|---|---|
| 今の周の、刻々と進むタイマー・時計 | 不可 | 10 秒より短い定期的な書き換え（明記） |
| 今の速度（メーター） | 不可 | 同上。例に出ている「エンジンの値」と同じ扱い |
| タイム差のバー・コース図・セクターの色分け | 不可 | 自分で描く画面は使えない |
| 測定開始・測定終了のボタン | 可（見込み） | 「運転の始めと終わりの作業」に当たる |
| 前の周・ベスト・差・周の数・前の周の最高速度（周を終えるたびに書き換え） | 可（見込み） | 周の区切りの出来事での書き換えで、10 秒より長い。ただし審査で「サーキットのタイムが運転を助けるか」を見られる |

ナビの分類（地図の部分を自分で描け、書き換えの間隔の決まりも違う）として「サーキット上のナビ」で申し込む手も考えたが、
ナビの許可は道案内（曲がる場所・経路）をするアプリに出るもので、周回するだけでは断られる見込みが高く、作る量（地図・ナビの型・案内）に対して得るものが少ないので見送った。

周ごとの読み上げ（音声）は、CarPlay につなぐと車のスピーカーから流れる（許可は要らない。今の作りのまま）。

## 4. 代わりの方法（参考）

- スマートフォンをホルダーで見やすい位置に付ける（今の作りのまま。利用者はこれで十分と判断）
- iPad・Android タブレットを付ける（iPad は対応の作業が要る）
- USB-C → HDMI で HDMI のモニターに映す（iPhone 17 Pro などは画面をそのまま映せる。車に HDMI の入力が無いので見送り）
