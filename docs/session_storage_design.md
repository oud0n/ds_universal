# 走行の情報・解析用のセッションの保存（設計の案）

2026-10-20。PLAN-18（解析用のセッションの保存）と PLAN-19（ラップタイマーの走行の管理）の続き。runs.json は 2026-10-24 に 2 版にした（docs/run_storage_v2.md。下の runs.json の例は 1 版のころの案）。走行は runs.json の行の `id`（変わらない印）と行の名前（日付のフォルダ/拡張子なしの名前）で指す。

## ねらい

- 「解析で開く」だけで、ログと動画と同期の結果がそろって開く。今の `.dssync.json` のように、自分でファイルを読み込み直さなくてよい。
- iPhone で記録した走行を、Mac のデスクトップ版でもそのまま見られる。iCloud Drive の同じフォルダを保管場所にする。
- ファイルから作り直せるもの（周の計算の結果）と、作り直せないもの（利用者が付けた情報）を分ける。作り直せないものだけを端末の間で共有する。

## フォルダの形

```
<保管場所>/
  sessions/
    <名前>.lapsession.json   解析用のセッション（PLAN-18）
  <サーキットのフォルダ>/    sodegaura など（英小文字・数字・_ だけ）
    20261024100000.bon4      走行（ラップタイマーが書く。外から置いてもよい）
    20261024100000.nmea
    GX010001.MP4             動画（同じフォルダに置いたものだけを走行に付けられる）
    laptimes.json            周の計算の結果（控え。端末ごとに作る。写さない）
    runs.json                走行の情報（利用者が付けたもの。端末の間で共有する）
```

## laptimes.json（控え）

今の形（lapIndex.ts）から、作り直せない情報（`hidden`・`videos`）を runs.json へ移す。残るのは、ファイルごとの印（大きさ・更新日時）と周の計算の結果、計算に使ったコースのハッシュだけ。消しても、次に一覧を開いたときに作り直せる。

## runs.json（走行の情報）

走行のファイル名ごとに 1 つ。

```json
{
  "version": 1,
  "runs": {
    "20261024100000.bon4": {
      "updatedAt": "2026-10-24T03:12:00Z",
      "hidden": [{ "n": 7, "startMs": 1792731123000 }],
      "clockOffsetSec": 0,
      "videos": [
        {
          "name": "GX010001.MP4",
          "size": 4012345678,
          "clock": { "source": "gpmf", "offsetSec": 0.12 },
          "pins": [{ "logTimeSec": 512.3, "videoTimeSec": 498.1 }]
        }
      ],
      "note": ""
    }
  }
}
```

- `hidden`: 隠した周。周の番号と始まりの時刻で持つ（計測線を直して周の番号が変わっても、時刻で引き継ぐ）。
- `videos`: 走行に付けた動画。同じフォルダのファイル名だけ（別のフォルダ・上のフォルダは指せない）。`clock` と `pins` は、今の `.dssync.json` の `clock`（VideoClock）と同期ピンと同じ中身。
- `clockOffsetSec`: ログの時計の補正。

### 端末の間でぶつかったとき

- 書くたびに、直前に読み直してから、変えた走行の行だけを差し替えて書く（読んで・直して・書くを短くする）。
- 走行の行ごとに `updatedAt` を持ち、ぶつかったら新しいほうを使う。`hidden` は両方を合わせる（隠す操作が消えないように）。
- iCloud が作るぶつかったときの写し（`runs 2.json` など）を見つけたら、上のやり方で合わせて、写しを消す。

## 解析用のセッション（sessions/<名前>.lapsession.json）

ファイルは写さず、走行を指すだけ。

```json
{
  "version": 1,
  "name": "袖ヶ浦 10/24 ベスト比べ",
  "createdAt": "2026-10-24T05:00:00Z",
  "course": { "folder": "sodegaura", "hash": "518f49c64580247e" },
  "cars": [
    { "slot": 1, "id": "r_mvlyxbes0410z2", "run": "sodegaura/20261024/20261024100000", "lap": 10 },
    { "slot": 2, "id": "r_mvm0c2kq7p1d4x", "run": "sodegaura/20260918/20260918092608", "lap": 11 }
  ],
  "video": { "main": { "id": "r_mvlyxbes0410z2", "name": "GX010001.MP4" } }
}
```

- 開くときは、指している走行を読み、runs.json の情報（動画・同期・時計の補正）を当てて、Car に割り当てる。
- 走行のファイルが無い・大きさが変わったときは、その Car だけ「見つかりません / 変わっています」と出す。
- コースのハッシュが今のコースと違うとき（計測線・セクター線を直したとき）は、知らせたうえで今のコースで数え直す。周の番号は時刻で合わせ直す。

## 今の .dssync.json からの移し替え

- 読み込んだ `.dssync.json` の動画とログを、ファイル名で保管場所の走行に照らし合わせ、見つかったものを runs.json の `videos`・`clockOffsetSec` に書く。
- 見つからないもの（保管場所の外のファイル）は、今までどおり `.dssync.json` で扱う。`.dssync.json` は読み込みだけ残す。

## 環境ごと

| 環境 | 保管場所 | runs.json・セッション |
|---|---|---|
| iPhone のアプリ | 書類の LapTimer/（選んだフォルダへ写す） | 選んだフォルダの runs.json を読み書きする（写すのではなく、そこで直す） |
| デスクトップ版 | 選んだフォルダ | そのまま読み書き |
| ブラウザ版 | なし | セッションのファイルを書き出す・読み込むだけ（ブラウザの中の記録は消えることがあるため） |

## 作る順番

1. runs.json を作り、`hidden`・`videos` を laptimes.json から移す（今の控えから引き継ぐ）。
2. 動画を走行に付ける画面（同じフォルダの動画から選ぶ。撮影の時刻が走行に重なる動画を先に出す）と、解析で開くときに動画も一緒に読み込むところ。
3. 動画の同期の結果（clock・pins）を runs.json に書く（動画の同期の画面の保存先を、走行があるときは runs.json にする）。
4. 解析用のセッションの保存と一覧（PLAN-18）。
5. `.dssync.json` からの移し替え。

## 決めたこと（2026-10-20）

- **runs.json は、選んだフォルダのものを直接読み書きする**（iPhone のアプリも）。iCloud Drive のフォルダも端末の中にあって直せるので、手元の写しは作らない。電波がなくても書け、つながったときに iCloud が送る。
- **動画は、選んだフォルダ（iCloud Drive）に置いてあるものを、そのまま読み込む**。端末にまだ落ちてきていない（iCloud からのダウンロードが要る）動画は、読み込む前に「ダウンロードが要ります（大きさ）」と知らせて、続けるか選んでもらう。数 GB の動画は、ファイルを丸ごと読まずに範囲を読み出す（PLAN-01 の動画の範囲の読み出しと一緒に）。
- 細かいところは、週末に使ってみてから決め直す。

## 決めたこと（2026-10-21）

- **iPhone のアプリで選んだフォルダを保管場所にしているとき、アプリの中 (LapTimer/) に走行の控えを残さない**（BUG-30）。書いている間はアプリの中に書き、ときどき選んだフォルダへ写す。測り終えた・取り込み終えたら (system.closeFiles)、選んだフォルダへ移してアプリの中から消す。控えを残すと、選んだフォルダで消したものを、次に開いたときに写し直して戻してしまうため。写せないとき (フォルダが使えない・書けない) だけアプリの中に残して、次に移す。
