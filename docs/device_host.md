# BLE・USBのホスト接続部品（PLAN-62）

2026-11-08。Web Serial / Web Bluetoothから独立した接続部品と、旧新の比較試験を追加した。Rust・OSドライバ、Electron/TauriのIPC実装、製品の接続先切替はまだない。既存画面は従来の通信層を使う。動画は対象外。

## 境界

```text
USB: 画面 → DigSpiceDevice / digspiceProtocol → LoggerTransport → ホスト → OS
BLE: 画面・BleLoggerLink / DeviceLink → BleCentral → ホスト → OS
```

- `src/services/deviceHost/contract.ts`: ホストの命令・通知・エラーの契約。JSONで渡せる値だけを使う。
- `serialTransport.ts`: `LoggerTransport`の実装。受信をバイト列のまま渡す。全量送信・部分書込み・並行writeの順序を管理する。
- `bleCentral.ts`: `BleCentral`の実装。探索・複数機器・特性の読書き・通知を既存の形へ変換する。再接続、権限、実GATT購読、MTUに応じた分割はホストが受け持つ。
- 既存のプロトコル、設定取得・ログ取得、各機器のデータ解析は流用する。USBの命令をBLEの位置通知へ流すものではない。

接続する側の例（ホストの実装と画面からの選択は後続）:

```ts
const usb = new HostSerialTransport(host, tr);
await device.connect(usb);
const ble = new HostBleCentral(host, tr);
const logger = new BleLoggerLink(async () => ble);
// 他の機器は new DeviceLink(registeredDevice, ble)
```

`tr`は日本語/英語の文言を選ぶ関数。省略時は日本語。自動的なWebへのフォールバックはない。BLEエラーは通信層ごとのクラスではなく`Error.code`で判定し、既存の権限案内・自動接続時のnot-found抑制を維持する。

## ホストが守る契約

この契約を満たしていない実機ドライバを、比較試験の合格だけで採用しない。

1. `listen`が完了してから命令を送る。解除は同期。通知は同じホスト内で発生順に届ける。命令の返事より早い通知も許す。
2. `session`は接続/探索ごとに新しい値とし、画面の読込み直しや複数窓を跨いで再利用しない。既定は`crypto.randomUUID()`。試験のID関数を製品に使わない。
3. `serial.close` / `ble.disconnect` / `ble.stopScan`は冪等。**open/connect/scanより先に取消しが届くことがある。** 終了したsessionを再開せず、後から完了したOS操作も片づける。終了応答までにそのsessionの保留要求・実購読・OS資源を解放する。応答しないopenを待ち続けてcloseを止めない。
4. USBはVID/PID `2dcf:6002`、115200 baud、8N1、フロー制御なし。DTR/RTSは既存Web経路と同じく設定を試し、未対応の場合は診断を残す。機器選択・OS権限はホストで行う。未対応の機器へ黙って接続しない。
5. USBの`serial.write`は実際に受け付けたバイト数を返す。アダプターが残りだけを送る。0・負数・範囲外を成功扱いしない。受信は行単位でなく任意分割で、順序を保つ。受信エラーで`serial.interrupted`、致命的な断線で`serial.lost`を一度送る。正常受信なしに5回中断すればアダプターも切断する。closeの通知をlostとして返さない。
6. BLEのconnectは要求受付まで。接続状況はstateで知らせる。電源断等の再試行は`reconnecting`、再試行しない終端は`disconnected`。`connected`は通知購読準備が完了してから送り、その後に通知を流す。再接続時には指定した全特性を購読し直す。
7. BLEの`epoch`はsession内で1から始め、再接続の試行ごとに増やす。状態と通知を同じepochで送る。古いOSコールバックに新しいepochを付け直さない。read/writeも指定epochだけに実行し、切断前に保留していた操作を次の接続へ送らない。GATT書込みの全量送信と必要な分割・順序はホストが保証する。write失敗時の自動的な全量再送はしない。
8. BLEの通知時刻`tMs`は受信時点の単調時計（ミリ秒）。全機器で同じ時計を使い、再接続でも基準を変えない。GPSのUTCやIPCを受け取った時刻へ置き換えない。複数通知の順序と特性の識別を保つ。
9. バイト列は0〜255の整数配列。1配列64 KiBまで。USBの大きな送信はアダプターが分割し、大きな受信はホストが分割する。BLEの1命令は64 KiBまで。無効な配列や非有限/負の時刻は通信失敗として扱う。
10. 失敗は`HostFault.code`で返す。診断用detailに鍵・利用者のログ等を入れない。権限拒否と機器不在を区別し、利用者向け文言は呼出し側で選ぶ。実装で使うIPCの権限・送信元もホストで制限する。

アダプターは明示終了時に先に購読と現sessionを無効化し、遅い結果を採用しない。USBの次のopen、BLEの同じ機器の次のconnect、次のscanは、それ以前の終了を全て待つ。A→B→Cと続けて置き換え、Bがホストへまだ接続していなくてもAの終了待ちを引き継ぐ。終了の一部が失敗しても他の終了を待ってから失敗を返す。自然な終端通知でもホストの終了待ちを予約してからコールバックを呼び、コールバックからの再接続が追い越さないようにする。重複したclose/disconnect/stopScanも進行中の終了完了を待つ。USBの自然切断はOSの後片づけを待つ前にonLostを届ける。BLEでは旧session・旧epochの通知を捨て、接続を跨いだread/writeの成功応答も取消しとして返す。

## 等価性の確認

比較の基準は型の一致ではなく、同じ操作と同じ合成入力に対する観測結果。旧経路と新経路のアダプターを実際に実行し、その上に同じ製品のプロトコルを載せる。旧実装は比較用に書き直さない。

| 対象 | 比較するもの | 追加の正解/異常条件 |
|---|---|---|
| USB設定・4096バイト取得 | 既存WebSerialTransport対HostSerialTransport。送信全バイト、設定全項目、取得全バイト | 合成機器の固定値/元画像とも照合。受信を1/2/7/64/65536バイトに分割、ブロック逆順/同一再送 |
| USB異常 | 欠落、同一アドレスの矛盾、チェックサム破損での失敗 | 両方が成功データを返さず、エラーと送信内容が一致する |
| USB中断・切断 | 途中行リセット、連続受信エラーの回数、応答待機中の断線 | 自然切断はタイムアウト前に待機を中止。明示closeはlostを出さない |
| BLE GATT | 既存webBluetoothCentral対HostBleCentral。探索結果、状態列、通知の順序/特性/バイト列、読取り値、書込み列、再購読 | offset付きDataViewと固定時刻で旧経路も実行する |
| BLE製品処理 | 同じDeviceLinkで心拍計/Drogger/RaceBox/GoPro/OBD、同じBleFixAssemblerでDigSpice A/B | 出力値と送信命令を一致させる。OBDはATZ応答→ATE0までで、全PID巡回を証明するものではない |
| エラーの扱い | NativeErrorと新ホストエラーを同じBleLoggerLinkへ渡す | 権限案内、自動接続時の機器不在抑制 |
| 新しい非同期境界 | 購読/open/connect受付前後の取消し、部分送信、旧通知/旧read/write完了、複数機器 | stale結果を採用しない、失敗を成功へ変えない。100回の探索/接続/終了で購読数が0へ戻る |

送信や取得の比較は全バイトの厳密比較。通知時刻の固定はアダプター変換の検査用であり、実機同士の到着時刻が等しいという主張ではない。実機比較では同じ時計へ対応付け、GPSの測位内容・欠測・受信間隔・最大遅延を別々に評価する。Webの機器選択画面とOSの探索UI、機器IDの文字列、RSSI、受信の分割サイズは完全一致の条件にしない。

```sh
npx vitest run src/services/deviceHost
npx tsc --noEmit -p .
npx vitest run
npm run build
```

全試験は合成機器で実行する。USB接続ボタンや本体の消去は操作しない。実ユーザーのログ・保管場所・機器は使わない。試験用の模擬ホストは実ドライバの検証の代わりにはならない。

## 次の採用条件

1. Electronの画面を維持したまま、OS側のUSB/BLEホストを別部品で実装する。製品へ切り替える前に、同じ比較用入力と失敗条件をその実装にも通す。
2. OS実装ごとに、取消しが先着する場合、旧epochのread/writeを実行しないこと、部分送信、再購読と資源解放を確認する。権限の拒否/取消し、アダプターOFF、スリープ/復帰、抜き差し、複数機器・同型機器を扱う。
3. 実機は別途許可された読取りだけの試験で確認する。USBは記録内容が変化しない条件で設定取得と取得ファイルの全バイト/SHA-256を照合する。記録中に内容が変わった差を通信の不一致としない。BLEの生きたGPS通知は別時点で内容が変わるため、同じ通知列の再生や、既知の連番/ペイロードを出す模擬周辺機器で厳密比較する。実ロガーでは測位/欠測/受信間隔/再接続を別に確認する。本体設定の変更・消去は今回の検証に含めない。
4. 同じ入力・操作時間でプロセス全体のメモリ、CPU、受信欠落、再接続時間を測る。この部品だけでElectronのメモリが減ったとは扱わない。
5. ここまで満たしてから製品の接続経路を切り替える。Tauriの採用と動画の移行可否は別に判断する。権限画面からOS設定を開く導線（openSettings）もホスト接続時に追加する。現在の部品はこの任意メソッドを持たず、native向けの設定ボタンまで接続済みとは扱わない。
