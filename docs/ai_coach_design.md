# AI のドライビングコーチの仕組み (PLAN-02、2026-10-21。検討だけ。まだ作らない)

## 方針

- AI は利用者が選ぶ。**手元のモデル** (パソコンで動かすもの) か、**利用者が自分で入れた API キー** のクラウドのモデル。アプリにキーは入れない。
- スマートフォンでは手元のモデルは使わない (重い・電池)。スマートフォンは API キーだけ。
- 動画の 1 コマずつを AI に見せる使い方 (大量の連続した画像) は、手元のパソコンでは現実的でないことが多い。画像を使う相談は API を前提にする。
- 数字 (速度・G・ブレーキの位置・ライン・セクタータイム) で相談するのが基本。画像は「このコーナーの数枚」のように絞って送る。

## 流れ

1. 解析の画面 (Car 1 と Car 2 を並べた状態) で「AI に聞く」。聞きたいこと (例: 「S2 で 0.3 秒負けている理由」) を選ぶか書く。
2. アプリが、送る中身を作って見せる (下の「送る中身」)。利用者が確かめてから送る (何を外に出すかを見せる)。
3. 答えを、解析の画面の横に出す。答えの中のコーナー・距離は、押すとグラフとコース図のその場所へ飛ぶ。
4. 相談の記録は、解析の保存 (.lapsession.json) に一緒に残せる (残すかは選ぶ)。

## 送る中身

- コース: 名前、コーナーの番号と位置 (コース図の距離)、セクターの区切り。
- 周ごとの要約: タイム、セクタータイム、各コーナーの進入速度・最低速度・脱出速度、ブレーキを始めた距離、最大の G、アクセルを開けた距離 (取れるログのとき)。
- 比べる周との差: 距離ごとのタイム差 (細かすぎないよう 10 m ごとなど)。
- 画像 (選んだときだけ・API のときだけ): そのコーナーの車載動画の数コマ (進入・頂点・脱出)。
- 送らない: 位置の生の点の全部、利用者の名前・端末の情報、保管場所の道。

## 選べる AI (設定 → AI)

| 種類 | 置き場所 | 動く所 |
|---|---|---|
| 手元のモデル (OpenAI 互換の API を出す LM Studio・Ollama など) | URL (例 http://127.0.0.1:1234/v1)・モデル名 | デスクトップ版だけ |
| API キー (Anthropic・OpenAI・Google など) | キーは端末の安全な置き場所 (iPhone はキーチェーン、デスクトップ版は OS の資格情報の保存)。画面の設定には出さない | どれでも |

- 1 つの共通の入口 (`askCoach(request): Promise<CoachAnswer>`) に、種類ごとの送り方をつなぐ。答えの形は同じにする (本文・指摘の一覧 (コーナー・距離・内容)・確かさ)。
- 料金の目安: 送る前に、おおよその大きさ (文字数・画像の枚数) を出す。

## 作るときに決めること

- コーナーの自動の切り出し (今のコーナー解析を使う) と、ブレーキ・アクセルの判定の閾値。
- 答えの形 (JSON で受け取り、画面で並べる) と、うまく返らないときの扱い。
- ブラウザ版で API キーを使うか (キーがブラウザに残る。使うなら毎回入れる形)。

# GoPro からの動画の取り込みの導線 (PLAN-21 の取り込みの部分、2026-10-21。導線だけ。作るのは後回し)

- 入口は 2 つ:
  1. 走行の詳細 (走行の画面) の「動画」の欄に「GoPro から取り込む」。その走行の時刻に撮った動画だけを、カメラの一覧から選ぶ (撮影の時刻で絞る)。
  2. 設定 → 機器 → GoPro の行に「動画を取り込む」(走行に関係なく、カメラの中身の一覧)。
- 取り込み: GoPro の Wi-Fi (Open GoPro の HTTP) で落とす。iPhone はカメラの Wi-Fi に一時的につなぐ。落とした動画は、走行と同じ日付のフォルダへ (動画の置き場所の方針どおり、写すかはここで選ぶ)。
- 取り込みの確認は、ログの取り込みの確認のシートと同じ部品を使う (動画の行: 撮影の時刻・長さ・大きさ・付ける走行)。
- 進み具合は、走行の画面の上の帯に出す (iCloud からの取り込みの帯と同じもの)。
