# コーナーの名前 (PLAN-27) の設計

2026-10-21。コースマップの編集で、コーナーの位置と名前を決め、コースのフォルダに置く。

## 今

- 解析の「コーナー別」とコースマップは、基準の周の曲がり具合からコーナーを見つけ (`drivingAnalysis.ts` の `detectCorners`)、見つけた順に C1, C2… と付ける。
- 周ごと・ログごとに見つけ直すので、走り方 (ライン) で数がずれることがある。公式の番号とも合わない (公式の「1-2 コーナー」が 2 つに分かれる、ゆるい曲がりが数に入らない など)。

## ファイル

`<保管場所>/<サーキットのフォルダ>/corners.json`

```json
{
  "version": 1,
  "course": "tsukuba2000",
  "corners": [
    {
      "name": "1",
      "direction": "R",
      "entry": { "lat": 36.15, "lon": 139.92 },
      "apex":  { "lat": 36.15, "lon": 139.92 },
      "exit":  { "lat": 36.15, "lon": 139.92 }
    }
  ],
  "auto": true,
  "updatedAt": "2026-10-21T12:00:00Z"
}
```

- 1 つのコーナーは、**入口・頂点・出口の 3 つの位置**と名前で持つ。距離 (スタートから何 m) では持たない。距離は計測線やラインで変わるため。
- 並び順はコースを走る順 (スタートからの順)。
- `auto: true` は自動で作ったまま、ユーザーがまだ直していないこと。名前を 1 つでも直したら false にする。
- コースのフォルダの名前 (`course`) は確かめのためだけに持つ。
- 同じサーキットの別のコース (筑波 2000 と 1000 など) は、フォルダが別なので別のファイルになる。

## 解析での使い方

1. コースに corners.json があれば、`detectCorners` の代わりに使う。それぞれの周で、入口・頂点・出口の位置にいちばん近い点を探し (同じ周の中で、前のコーナーの出口より後ろから探す)、今の `Corner` の形 (startIndex・apexIndex・endIndex など) にする。名前は `name`。
2. 周の点が位置から 30 m より遠い (コースを外れた・ピットに入った など) ときは、そのコーナーを「対応区間なし」にする。今の `measureCorners` と同じ。
3. corners.json がないコースは、今までどおり見つけた順に C1…。

## 今あるコースの自動作成

- 保管場所のコースのフォルダに corners.json がなければ、そのコースの記録の中でいちばん速い周 (laptimes.json の、隠していない周) から `detectCorners` で見つけ、C1… の名前で作る (`auto: true`)。
- 作るのは、走行の画面で一覧を作ったとき (laptimes.json を作り直すのと同じ時)。ファイルを書けるのは、iPhone のアプリとデスクトップ版。
- ブラウザ版は保管場所がないので、そのときの周から見つけたもの (今までどおり) を出す。
- 最初から入っているコースに名前を入れて配ることはしない (コースの座標を写さない方針)。

## コースマップの編集

コースマップに「コーナー」の編集の段を足す。地図の上で、それぞれのコーナーの頂点に名前の札を出す。

- **名前を付ける**: 札を押して名前を入れる (「1」「ヘアピン」「ダンロップ」など自由に)。
- **まとめる**: 並んだ 2 つを選んで「まとめる」。前の入口から後ろの出口までを 1 つにし、頂点は曲がりのきついほうにする (公式の「1-2 コーナー」)。
- **分ける**: 1 つを選んで「分ける」。曲がりのいちばんゆるい所で 2 つに分ける。
- **足す**: 見つからなかったゆるい曲がりに、地図を押して足す。入口・出口は押した所の前後 (曲がり具合から決める)。
- **消す**: 直線の小さな揺れなどを消す。
- **作り直す**: 今の周から見つけ直す (名前は、近い位置のものを引き継ぐ)。
- 保存すると corners.json を書き換える (この画面からだけ。上書きの前に前の中身を `corners.json.bak` に 1 つ残す)。
