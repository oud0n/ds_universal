# 内蔵のコースデータ

アプリに同梱しているコースのデータです。デジスパイスのコースフォルダと同じ形式のファイルで置いています。

| ファイル | 中身 |
|---|---|
| `index.json` | コースの一覧（ID・名前・国・中心の座標・ファイル名・作り方のメモ） |
| `<id>.cln` | 計測線（コントロールライン）。1 行目が本数（1）、続く 4 行が 緯度A・経度A・緯度B・経度B |
| `<id>.sci` | セクター線。1 行 1 本「緯度A,経度A,緯度B,経度B,1」。公式の .sci と同じく、フィニッシュ（計測線）は含まない |

- 改行は CRLF、座標は小数 6 桁（公式のファイルと同じ）。
- アプリはビルドのときにこのフォルダのファイルを取り込みます（`src/services/circuitDatabase.ts`）。
- セクター線の並びが走る向きと逆でも、アプリが周回の計算で並べ直します。

## 作り方

- **中心の座標**: OpenStreetMap のコースの形（`highway=raceway`）の外接矩形の中心。
- **計測線**: 国土地理院の航空写真で、路面のコントロールラインや計測のゲートの位置を確かめ、OpenStreetMap のコースの中心線に直交する線として置いた。公式の計測位置と一致するとは限らない。
- **セクター線**: OpenStreetMap のコースの中心線の上に、計測線からの距離で置いた。区切りの決め方はコースごとに次のどれか（`index.json` の `notes.sectors` に書いてある）。
  1. 公式の資料に計測地点があるもの: その距離（SUGO）。
  2. 公式の区切りが分からないが、レースの区間の分け方が分かるもの: そのコーナーの位置から推定（鈴鹿・富士）。
  3. 区間の数だけ分かるもの: 1 周をその数で等分（もてぎ: 4）。
  4. どれも分からないもの: 1 周を 3 等分。等分の位置の近くにほかの直線が並んでいるときは、少しずらす。
- Google マップの航空写真や、他のアプリ・公式ソフトのコースデータは使わない（規約・権利のため）。

## 直してほしいとき・コースを足してほしいとき

[Issue](https://github.com/oud0n/ds_universal/issues/new?template=course.yml) でお知らせください。

- 計測線・セクター線がずれているときは、アプリの「コース編集」で直した線を .cln / .sci で書き出して添付してもらえると早く直せます。
- 実際の公式の区切り（セクターの位置）が分かる資料があれば、その場所も教えてください。
- このフォルダのファイルを直接直した Pull Request も歓迎します。データは自分で作ったもの（再配布できるもの）に限ります。他のアプリや公式ソフトのデータの写しは受け付けられません。
